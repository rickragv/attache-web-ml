1The concept

One coherent app, not four disconnected demos.

Attaché is a briefcase you can talk to: drop in your own documents (or use the seeded corpus), then speak or type a question. Everything that happens next — transcription, routing, semantic search, reranking, and answer synthesis — runs inside the browser tab. No server, no upload, no API key. Pull the network plug mid-demo and it keeps working; that moment is the pitch.

The app is a single-page pipeline with four stations plus a stretch capstone. Each station is independently explorable (click into it, tweak inputs, watch tensors move), but the headline interaction is the relay: a spoken question flows left-to-right through all of them. This keeps the demo domain-neutral — the seeded corpus is generic knowledge-base articles — while every station corresponds exactly to a Vitark target:

Why this shape wins as a showcase: three of the five stations share one EmbeddingGemma download, so the demo feels rich while costing one model fetch; the relay tells a story any audience understands ("I asked my files a question, out loud, offline"); and each station doubles as the proof-of-concept for a specific Vitark feature, so the demo is reusable engineering, not throwaway theatre.

2The stations in detail

Station A

Recall — ask your own documents

Build first

Drag ten .txt/.md files onto the page. Two seconds later they're semantically searchable. They never left your machine.

Interaction
Drop zone + seeded corpus (~30 short knowledge-base articles). Each document is chunked (~200 tokens, overlap 40), embedded in a Web Worker, stored in IndexedDB. As-you-type query embedding + cosine top-k with animated similarity scores on each result card.
Showcases
The exact pattern from Google's official EmbeddingGemma vector-search demo — loadAndCompile(..., {accelerator: 'webgpu'}), batched tensor runs, WASM fallback.
Proof element
Per-query latency readout ("embedded in 18 ms · WebGPU") + an offline toggle that kills fetch and shows recall still working.
Station B

Triage — zero-shot routing, editable live

Same model

The demo ships with routing labels — Billing, Bug report, How-to, Feedback, Spam — and the audience can rewrite them on stage. No retraining, instant new classifier.

Interaction
A label editor (add/remove/rename categories, each with 2–3 example phrases). Labels become prototype embeddings; incoming queries classify by nearest prototype with a confidence bar. A "gate" visual shows low-value queries (spam/greetings) being stopped before the "expensive pipeline" — the Vitark credits story, told generically.
Showcases
That one embedding model is a family of classifiers; recomputing five prototypes takes milliseconds, which no server API can match interactively.
Station C

Rerank — keyword order vs. semantic order

Same model

Left column: what naive keyword search returns. Right column: the same ten results re-scored semantically, reordering live as you refine the question.

Interaction
A tiny BM25 (plain JS, ~80 lines) produces the "before" list; embedding similarity re-scores it into the "after" list with animated rank movement arrows. Queries chosen to make keyword search fail visibly (synonyms, paraphrase: "my payment didn't go through" vs. docs saying "transaction declined").
Showcases
The reranking economics: this re-score is a paid per-call API server-side (Vitark pays Vertex Ranking); here it's free and ~20 ms.
Station D

Dictate — speech in, text out, mic never uploads

Second model

Hold the mic button, ask your question out loud, watch the transcript type itself into the search box and flow through the pipeline.

Interaction
Push-to-talk (not always-on streaming — deliberately scoped down): record up to 30 s via getUserMedia, resample to 16 kHz mono, compute log-mel spectrogram in the worker, run Whisper encoder/decoder, emit transcript. A live waveform + "audio stays here" badge.
Showcases
LiteRT.js on audio models — the workload class Google benchmarks at 5–60× on WebGPU. Push-to-talk keeps us off the hard streaming-ASR path while still landing the wow.
Risk note
Whisper .tflite I/O varies by export (some bundle the mel frontend, some don't; decoder may be autoregressive loop in JS). Phase 0 pins this down; whisper-tiny (~40 MB) first, whisper-base if quality disappoints.
Capstone

Answer — Gemma writes the grounded reply

Stretch

The top three reranked passages plus your question go to Gemma running in the tab; a cited answer streams out token by token, with tokens/s on the HUD.

Interaction
Answer panel with streaming text and passage citations [1][2][3]. Completes the story: the browser just did full RAG — retrieval, ranking, and generation — with zero server involvement.
Risk note
Depends on LiteRT-LM's browser bindings (gemma-4-E2B-it-litert-lm is a multi-GB download; needs WebGPU headroom). Phase 0 verifies the current npm surface; if it's not demo-stable, the fallback is showing the pipeline hand off to any LLM with a "generation is pluggable" framing. The four stations stand on their own.

Main thread renders; workers infer; nothing blocks a keystroke.

StoresCache API: model weights · IndexedDB: chunk vectors · in-mem: BM25 index

Workers own model lifecycle and expose a typed message protocol ({type:'embed', texts[]} → {vectors, ms, backend}). The perf HUD is fed from worker telemetry: active accelerator, per-op latency, model cache state, cumulative "server calls made: 0".

Verified technical ground

  • Runtime: npm i @litertjs/core; WASM assets copied from node_modules/@litertjs/core/wasm/ into public/wasm/; loadLiteRt() once per worker, then loadAndCompile(url, {accelerator: 'webgpu'}) with automatic CPU fallback for unsupported ops.
  • Models (Hugging Face, all confirmed to exist): litert-community/embeddinggemma-300m, litert-community/whisper-tiny, litert-community/whisper-base, litert-community/gemma-4-E2B-it-litert-lm. Fetched at runtime with a progress bar, persisted via Cache API — the repo stays lightweight.
  • Vite: COOP/COEP headers in dev config (worker + WASM threads want cross-origin isolation); static deploy target (GitHub Pages / Cloud Run static) needs the same two headers.

4Build phases

Phase 01 day

Spike — pin every unknown

  • Bare Vite page: load EmbeddingGemma via @litertjs/core; measure download, compile time, per-embedding ms on WebGPU vs. WASM on your machine.
  • Inspect whisper-tiny I/O with getInputDetails() — does it want raw audio or mel features? Autoregressive decode loop needed?
  • Verify LiteRT-LM's current browser package for Gemma; go/no-go the capstone.
Phase 12–3 days

Core app — Recall + Triage + Rerank on one model

  • App shell, embed worker, model cache with progress UI, seeded corpus, drop zone.
  • All three embedding stations working end-to-end with the perf HUD.
  • This alone is a complete, presentable demo — everything after is amplification.
Phase 22–3 days

Dictate + theatre

  • Push-to-talk Whisper station; transcript feeds the relay.
  • Offline toggle, "before/after" keyword-vs-semantic animation, cumulative-zero-server-calls counter, polish pass on the relay flow.
Phase 32–4 days, stretch

Gemma capstone + ship

  • LiteRT-LM answer station with streaming tokens and citations (if Phase 0 said go).
  • Static deploy with COOP/COEP headers; recorded GIF walkthrough; README mapping each station back to its Vitark integration point.

5Risks, stated plainly

  • Whisper export variance is the likeliest schedule risk — the mel frontend and decode loop may need hand-rolling in JS. Mitigation: push-to-talk scope, Phase 0 inspection, parakeet models as alternates if Whisper exports fight back.
  • Gemma in-browser is genuinely bleeding-edge — multi-GB weights, WebGPU memory pressure, young npm surface. It's structured as a capstone precisely so its failure can't sink the demo.
  • First-load weight: ~200 MB (EmbeddingGemma) + ~40 MB (Whisper) before the capstone. Mitigation: progressive loading (Station A usable while D downloads), Cache API so it's once per machine, and the progress bar framed as part of the story ("this is the whole AI, arriving").
  • Safari: WebGPU is newer there; WASM/XNNPACK path must be tested as a first-class citizen, and the HUD's backend badge makes the fallback visible rather than embarrassing.
