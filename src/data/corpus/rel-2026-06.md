# Release notes — June 2026 (platform v2026.06)

Completed rollout 2026-06-18. API changes ship under `Meridian-Version: 2026-06-10`.

## New

- **Webhook event replay.** Replay any event from the last 30 days to a chosen endpoint: Dashboard → Developers → Webhooks → Replay, or `POST /v1/events/{evt_id}/replay`. Replays carry header `X-Meridian-Replay: true` and a fresh signature.
- **Same-day settlement (Batch B) self-serve.** The 15:00 IST Early Settlement batch can now be enabled without contacting support for accounts older than 180 days with dispute rate < 0.3%. Pricing: 0.10% of batch value.
- **Checkout v3.4 — address autofill.** Pincode-first address entry with postal directory lookup; reduces billing-address abandonment on international card flows by a measured 12%.

## Improved

- 429 responses now always include `Retry-After`; previously omitted on burst-tier throttles.
- UPI collect: configurable `expiry_minutes` (2–5) exposed on `POST /v1/payments`, previously account-level only.
- Dashboard dispute view shows the network `respond_by` deadline in IST with a countdown, plus calendar export.

## Fixed

- Duplicate `refund.processed` webhooks (~0.02% of refunds) when a bank ACK raced the retry timer — deduplication is still recommended, but the race is closed.
- Settlement CSV occasionally rendered UTRs in scientific notation when opened in Excel; UTR column is now explicitly quoted.

## Feature flags

- `webhook_replay` — default on.
- `checkout_address_autofill` — default on for v3.4+; pinned-version integrations unaffected.

## Deprecations

- TLS 1.1 connections to `api.meridianpay.in` are rejected as of 2026-06-30 (announced 2025-12).
