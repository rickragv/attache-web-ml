1The opportunity

Why a text-heavy legal platform is a strong fit for browser inference.

LiteRT.js is Google's successor to TensorFlow.js for running .tflite models directly in the browser — XNNPACK on CPU/WASM, ML Drift on WebGPU, with claimed 5–60× GPU speedups over CPU on real-time workloads. Models convert from PyTorch/JAX/TF in one step and ship from the Hugging Face LiteRT community. The npm package is @litertjs/core.

Today, every intelligent behaviour in Vitark is a paid server round-trip: the Gemini coordinator agent triages even a "hello", retrieval fans out through the MCP service, reranking pays the Vertex AI Ranking API per call, and each research call debits user credits. There is currently zero client-side ML in the frontend. That means every place where a small model in the browser can answer in ~10 ms for free is currently either a billable LLM call or simply doesn't exist as a feature.

On-device inference earns its place through four levers. Every use case below is scored against them:

PrivacyLawyer's client facts never leave the machine — attorney–client privilege is the strongest possible on-device argument.
CostReplaces billable Gemini / Vertex Ranking calls with free client compute. Protects both your margin and the user's credits.
Latency~10–50 ms as-you-type feedback vs. a 1–3 s server round-trip. Enables interactions that are impossible over the network.
OfflineIndian courtrooms have genuinely unreliable connectivity. A lawyer's own research should still be searchable at the bar.

2Top 5 production use cases, ranked

Ranked by (value to Vitark × feasibility). Highlighted chips = levers that apply.

Nº 1

Chamber Recall — semantic search over your own research

Demo pick Low risk

"Before I burn credits, has my chamber already researched anticipatory bail under S. 438 for economic offences?" — instant, even offline in the courtroom.

What it does
Embeds every memo in the user's Chamber (and session history) locally with EmbeddingGemma; as the user types in the search bar, a vector search over their own archive surfaces prior memos before they spend credits on a new research run.
Why on-device
PrivacyCostLatencyOffline
Model
EmbeddingGemma-300M (.tflite, quantized ≈ 150–200 MB, multilingual incl. Hindi) — the exact model Google's official LiteRT.js vector-search demo uses, so the path is proven.
Integration
ChamberPage.jsx + SessionPanel + SearchBar; embeddings cached in IndexedDB per memo.
Nº 2

Zero-credit query triage & smart routing

Demo pick Low risk

The user types a query; before anything is billed, the browser already knows: is it legal? English or Hindi? Which of the 13 categories? Which pipeline should run?

What it does
As-you-type classification via embedding similarity against category prototypes: flags non-legal/junk queries (today a paid Gemini coordinator call does this), detects EN/HI, predicts legal category, and pre-fills the /cases filter set. Bad queries never reach the paid pipeline.
Why on-device
CostLatencyPrivacyOffline
Model
Same EmbeddingGemma-300M as Nº 1 — one download powers both features. Category prototypes are just pre-computed embeddings of the 13 category_l1 labels + exemplar queries.
Integration
SearchBar in PractitionerApp.jsx; gate before the AG-UI SSE call in backend_service; filter pre-fill in CaseLookupPage.jsx.
Nº 3

Privilege Guard — client-side PII detection & redaction

Medium risk

A lawyer pastes real client facts into a query. Before the text leaves the browser, names, phone numbers, and addresses are highlighted with a one-click "redact & substitute" offer.

What it does
On-device NER over the query text; detected entities are replaced with neutral placeholders ("the accused", "the complainant") locally, so privileged identity details never reach Vitark's servers, Gemini, or logs. Enormously strong story for legal sales conversations.
Why on-device
PrivacyLatencyCostOffline
Model
MobileBERT-class NER .tflite (≈ 25 MB int8), regexes for phones/CNR/emails. Risk: Hindi/Devanagari NER coverage needs evaluation; Indian-name recall must be tested.
Integration
Pre-submit hook in SearchBar; also valuable in Deep-Dive chat input.
Nº 4

Client-side case reranking in Deep Dive

Medium risk

In a Deep-Dive follow-up, the 25 cases already on screen instantly reorder by relevance to the new question — no server call, no Vertex Ranking fee.

What it does
The main pipeline already delivers cases with snippets to the client (cases_preview SSE feed, Cases Discussed table). Re-scoring those against follow-up questions locally offloads a slice of the per-call semantic-ranker-default-004 spend and makes result exploration feel instant.
Why on-device
CostLatencyPrivacyOffline
Model
EmbeddingGemma bi-encoder scoring (shared with Nº 1–2), or a small cross-encoder .tflite for higher fidelity. Risk: quality vs. Vertex's cross-encoder must be measured before replacing anything server-side.
Integration
CasesPreview / ResponseCard components; Deep-Dive panel in PractitionerApp.jsx.
Nº 5

Bilingual voice dictation (EN + Hindi)

Higher risk

A lawyer on a phone between hearings dictates: "धारा 138 एनआई एक्ट में समन के बाद समझौता" — transcribed on-device, audio never uploaded.

What it does
On-device ASR for query input. Google's LiteRT.js benchmarks specifically call out transcription as a 5–60× WebGPU win, and the audio-never-leaves-the-device framing matches the privilege story.
Why on-device
PrivacyLatencyCostOffline
Model
Whisper-tiny/base class .tflite (≈ 40–150 MB). Risk: streaming mic pipelines in-browser are fiddly; Hindi legal-vocabulary accuracy at small model sizes is unproven — prototype later, not first.
Integration
Mic button on SearchBar; mobile-first.

Recommendation: build Nº 1 + Nº 2 together as one demo — the "Query Intelligence Bar". Both run on a single EmbeddingGemma download, both sit on the same surface (the search bar), and together they demo every lever in one interaction: type a query → the browser instantly classifies it, detects language, suggests filters, and surfaces your own prior research — all before a single credit is spent or a single byte leaves the machine. It's also the lowest-risk path: it mirrors Google's own official LiteRT.js vector-search demo, so we're productionizing a proven pattern, not pioneering one.

5Build plan

Phase 0½–1 day

Feasibility spike

Load EmbeddingGemma via @litertjs/core in a bare Vite page in E:\clone\web-ml. Measure: model download size, cold compile time, per-embedding latency on WebGPU vs. WASM, and Hindi embedding sanity. Go/no-go gate for model choice.

Phase 12–3 days

Standalone demo app

  • Vite + React page styled to Vitark's editorial look, with a seed corpus of ~20 realistic legal memos (mixed EN/HI, spanning the 13 categories).
  • Live triage chips (legal/junk · language · category) and Chamber-recall results rendering as-you-type.
  • Perf HUD: backend badge, inference ms, model cache status, "0 credits spent" counter as the narrative hook.
Phase 21–2 days

Hardening the demo

  • Cache API model persistence + download progress; graceful WASM fallback where WebGPU is absent (Safari/older hardware).
  • An offline toggle in the demo: cut the network, show recall still working — the courtroom story, made visceral.
  • Side-by-side "before/after": server triage (~2 s, costs a credit) vs. on-device (~30 ms, free).
Phase 3later

Vitark integration

Port as frontend/src/shared/ml/ with a useLiteRT hook beside the existing hooks; wire into SearchBar, ChamberPage, and the pre-submit gate; feature-flag it like CHAMBER_ENABLED. Nº 3 (Privilege Guard) becomes the natural second shipment on the same infrastructure.

6Honest risks

  • Model download weight. EmbeddingGemma quantized is on the order of 150–200 MB — fine cached on a lawyer's laptop, heavy on first mobile load. Mitigation: background fetch after first paint, progress UI, Cache API persistence; evaluate smaller universal-sentence-encoder-class fallbacks if the spike says so.
  • WebGPU coverage. Excellent on Chrome/Edge desktop, newer on Safari; WASM/XNNPACK fallback must be a first-class path, not an afterthought — embedding workloads remain usable on CPU.
  • Hindi quality. EmbeddingGemma is multilingual and should handle Devanagari, but legal-domain Hindi must be spot-checked in Phase 0 before promising the bilingual story.
  • Don't oversell replacement. On-device triage/recall augments the paid pipeline (it guards its entrance); it does not replace Vertex reranking or the ADK agents. The demo should frame it as the free, private front door to the paid engine.
